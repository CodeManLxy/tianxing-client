# 天行健客户端与通信 EA 安装使用说明

适用版本：客户端 **2.6.0**，通信 EA **2.50**。更新日期：2026-10-30。

本仓库提供客户端和通信 EA。**天行健 SMC 纯指标不在仓库中，需使用你已有的兼容指标 1.02，并开启数据导出。普通只画线、没有本项目数据导出的 SMC 指标不能直接替代。**

## 1. 先理解三个组成部分

| 组成 | 安装位置 | 负责什么 |
| --- | --- | --- |
| 天行健客户端 | Windows 桌面 | API、AI 对话、Skills、风险预算、交易表单及回执 |
| TianXingBridge 通信 EA | 一个 MT5 图表 | 读取实际账户和图表数据，转发指标输出，验证并执行客户端指令 |
| 已有 SMC 纯指标 1.02 | 每个需要分析的周期图表 | 计算并导出真实结构、OB、FVG 等数据；不由客户端重建 |

同一个终端只挂**一个**通信 EA。例如要分析 XAUUSD 的 M5、M15、H1：打开三个图表，各挂一份 SMC 指标；通信 EA 只挂在其中一张图表。它可以读取同一终端其他图表的指标输出。

通信采用本机公共文件，不需要给通信 EA 填模型 API Key，也不依赖 DLL 或 EA 的 WebRequest 地址白名单。MT5 与客户端应在同一台 Windows、同一用户下运行；跨电脑文件共享不属于当前默认配置。

## 2. 下载文件与启动客户端

### 方式 A：你已有完整客户端程序包

1. 关闭正在运行的旧客户端。
2. 解压完整程序目录，保留 `resources` 等文件，不能只复制一个 EXE。
3. 双击 `TianXingJian.exe`。

已有 API 设置、Skills 和聊天通常沿用同一 Windows 用户的客户端档案。退出客户端不会撤销券商端的已有订单。

### 方式 B：从本仓库源码运行

GitHub 的 **Code → Download ZIP 是源码包**，不是已打包的 Windows 客户端。下载后解压，在包含 `package.json` 的文件夹打开 PowerShell。先安装 Node.js 22，然后运行：

```powershell
npm ci
npm start
```

无需安装 Python，也无需在客户端另填 MT5 账户密码；由你已登录的 MT5 终端提供账户数据。首次安装依赖可能下载 Electron，需要正常访问 npm 和 Electron 官方分发服务。

需要生成桌面程序时，在源码目录运行：

```powershell
npm run package
```

程序位于 `dist/TianXingJian-win32-x64/TianXingJian.exe`，分发时保留整个该目录。打包会包含仓库中列出的通信 EA 文件，**不会自动获得或生成未提供的指标**。

## 3. 安装通信 EA

仓库的 [`mt5/`](../mt5/) 包含以下 4 个运行/编译文件：

| 文件 | 用途 |
| --- | --- |
| `TianXingBridge.ex5` | 已编译 EA，可直接挂载 |
| `TianXingBridge.mq5` | 通信 EA 主源码 |
| `Json.mqh` | JSON 依赖，编译时需要 |
| `SMCRead.mqh` | 指标数据读取依赖，编译时需要；不是指标算法 |

### 推荐：通过客户端安装

1. 在目标 MT5 点击 **文件 → 打开数据文件夹**。
2. 记住打开的目录。这里应能看到 `MQL5` 子目录；它不是 MT5 安装目录，也不是 `MQL5` 子目录本身。
3. 客户端进入 **连接与设置 → 安装通信 EA 到 MT5**。
4. 选择第 1 步打开的**数据目录根目录**。
5. 安装器复制 4 个通信文件到 `MQL5/Experts/TianXingBridge/`。若该目录已存在，先复制一份带时间戳的备份。
6. 返回 MT5，在导航器的 EA 列表中刷新，找到 `TianXingBridge`。

复制文件不会自动将新版载入已运行的图表。升级后需要在图表重新加载通信 EA，详情见第 10 节。

### 手动安装

把上述 4 个文件复制到目标 MT5 的：

```text
<MT5 数据目录>/MQL5/Experts/TianXingBridge/
```

目录应类似：

```text
MQL5/
  Experts/
    TianXingBridge/
      TianXingBridge.ex5
      TianXingBridge.mq5
      Json.mqh
      SMCRead.mqh
```

使用已有 `.ex5` 可直接安装；如终端提示编译文件不兼容，或你修改了源码，在 MetaEditor 打开 `TianXingBridge.mq5`，确保两个 `.mqh` 仍在同一目录，再按 **F7 编译**。只编译 EA 主文件，不要把 `.mqh` 当 EA 挂载。[MetaEditor 官方编译说明](https://www.metatrader5.com/en/metaeditor/help/development/compile)

文件校验见 [`mt5/SHA256SUMS.txt`](../mt5/SHA256SUMS.txt)。在 PowerShell 中可运行：

```powershell
Get-FileHash .\mt5\TianXingBridge.ex5 -Algorithm SHA256
```

## 4. 挂载 EA 和指标

### 4.1 准备图表

1. 登录你要使用的 MT5 账户，确认报价正常更新。
2. 为所需品种分别打开 M5、M15、H1 等图表，保留各自独立图表。不要在一张图上反复切周期来代替多张图表同时导出。
3. 每张需要分析的图表挂载你已有的天行健 SMC 纯指标 1.02。
4. 在指标参数中开启 `InpExportAIData`（向 AI 导出数据）。等待历史数据和指标初始化完成。
5. 每张图表只挂一份该 SMC 指标。客户端是否可读以“图表证据”实际显示为准。

### 4.2 挂一个通信 EA

把 `TianXingBridge` 拖到一张图表，核对版本显示为 **2.50**。四个输入参数如下：

| 参数 | 默认值 | 如何设置 |
| --- | --- | --- |
| `InpBridgeId` | `default` | 通信名称，必须与客户端一致；不是周期名称 |
| `InpAllowTrading` | `false` | 只分析时保留 `false`；需要提交交易时设置 `true` |
| `InpHistoryDays` | `7` | 成交历史统计天数，程序按 1–90 天处理 |
| `InpMagic` | `2601030` | 客户端新订单 Magic；周期归属还通过客户端策略标记跟踪 |

通信名称只接受英文字母、数字、下划线、横线，长度 1–64。新安装可统一用 `default`；如果你已经使用 `1` 或其他名称，EA 与客户端都使用那个名称即可。**多个周期共用同一个通信名称，不要给 M5、M15、H1 分别挂通信 EA。**

MT5 一个图表只能运行一个 EA。不要把通信 EA 拖到正在运行其他交易 EA 的图表并误替换它；可另开一张图表作为通信图表。[MT5 官方 EA 与指标说明](https://www.metatrader5.com/en/terminal/help/algotrading/trade_robots_indicators)

## 5. 配置模型 API

在客户端 **连接与设置** 中：

1. 选择服务商。
2. 填服务商提供的 API 地址、准确模型 ID 和 API Key。这里不需要 MT5 账户密码。
3. 确认接口协议：兼容服务常用 Chat Completions；Claude 常用 Messages；支持 Responses 的路由选择 Responses。以你所用服务的实际接口为准。
4. 不确定思考参数兼容性时保留服务商默认；先用服务商支持的准确模型名称。
5. 点击 **保存设置**，再点击 **测试连接**。
6. 点击 **测试工具调用**，确认模型能调用工具并接收返回。仅能回复文字并不代表能读取 MT5 或执行多周期工具流程。

不同服务商独立保存配置；修改后先保存再测试。密钥不回显，留空一般保留已保存密钥，清除密钥需勾选对应选项。远程模型地址要求 HTTPS，本机代理可使用 localhost HTTP。

API Key 不填在 EA 或技能里。技能正文和模型实际读取的行情/账户数据会发送给你选定的模型服务商。

## 6. 连通检查与交易权限

### 6.1 先核对通信目录

客户端的“公共 Files 目录”默认是：

```text
%APPDATA%\MetaQuotes\Terminal\Common\Files
```

它与第 3 节安装 EA 时选的“终端数据目录”不同。公共 Files 用来通信，数据目录用来存放该终端的 EA。公共文件机制对应 MT5 的 `FILE_COMMON`。[MQL5 官方 FileOpen 说明](https://www.mql5.com/en/docs/files/fileopen)

如果通信名称为 `default`，实际通信子目录为：

```text
<公共 Files>/TXJ_Client/default/
```

在 **连接与设置 → 检查 MT5 连接** 中核对通信目录、EA 版本、心跳时间、券商连接和同步耗时。正常应看到：

- 左下角显示“MT5 已连接”，账户与你当前目标终端一致。
- 诊断中 EA 为 2.50，心跳持续更新。
- 图表证据出现已挂指标的品种与周期，并显示结构可读。
- 挂单、持仓和账户数据与 MT5 一致；空表也可能是该账户确实没有订单。

账户、挂单、持仓和指标按约 1 秒刷新，历史成交缓存约 15 秒。心跳超过 5 秒提示同步延迟，超过 30 秒离线；指标证据和报价还要独立检查时效，不能把在线心跳当成行情仍然有效。

### 6.2 三种使用方式

| 方式 | EA 与终端权限 | 客户端操作 |
| --- | --- | --- |
| 只分析 | `InpAllowTrading=false` 即可读取数据 | 关闭 AI 开关，或消息明确写“仅分析，不下单” |
| 人工确认交易 | EA `InpAllowTrading=true`，终端/该 EA 允许算法交易，账户允许交易 | AI 开关关闭，计划填入交易页后逐笔原生确认 |
| AI 直接新挂单 | 同上，并有有效账户/目录绑定 | 开启“允许 AI 直接挂单”，发送交易分析请求；无需逐笔确认弹窗 |

打开开关本身不会下单，也不会启动定时循环。切换账户、服务器或通信目录后，需要关闭再开启开关，绑定新的目标。权限不足会显示具体原因，提示词不能绕过这些校验。

AI 直接执行只支持新建 `BUY_LIMIT` / `SELL_LIMIT`。撤单、改单和平仓仍通过交易页人工确认。停止分析或关闭开关只阻止尚未发送的新指令，不会自动撤销已发送订单。

## 7. Skills 的日常使用

“Skills 管理”可以新建、编辑、保存、启停、导入、导出技能。每个技能目录包含 `SKILL.md`，可附 Markdown、文本或 JSON 参考文件。保存后用于下一轮分析；文件不会作为脚本执行。

仓库首装提供 `smc-ob-fvg` 和 `smc-data-reading` 两份客户端技能。已有用户可能保留之前导入的技能，它们来自本机档案，不代表仓库含有那些旧项目源码。

单周期策略默认继承全局启用项。若要 M5、M15、H1 使用不同组合，先在单周期模式切换到对应图表，在右侧勾选“单独选择技能”并选择组合。联合分析会分别沿用这些配置。客户端 Skills 与 Codex 的技能目录相互独立。

## 8. 多周期分析与挂单

详见 [多周期分析指南](多周期分析指南.md)，其中区分：

1. **三个周期各自评估、各挂一笔**：使用“多周期联合分析”，勾选目标周期，一次发送。
2. **H1/M15 判断背景，只有 M5 挂单**：使用“单周期策略”，执行图表选 M5，提示 AI 读取其他已挂指标的周期作辅助。

不要仅在单周期提示词中写“给三个周期都下单”；单周期的执行范围仍只允许所选图表。

## 9. 查看订单、回执和盈亏

联合分析页显示各周期最新批次回执；“交易与盈亏”可切换当前挂单、持仓、成交历史和指令回执，并按策略筛选。策略记录绑定账户、服务器、通信目录、品种和周期。无法追溯的旧单会显示“其他 / 旧版订单”，不按品种猜测来源。

| 状态 | 含义 | 后续处理 |
| --- | --- | --- |
| 未提交 / 等待 | 该周期未写入执行指令 | 查看条件不足或中断原因 |
| 等待 EA 接收 | 已写入本机队列 | 等待自动更新，避免重复点击 |
| EA 处理中 | 执行日志已有记录 | 等待最终回执 |
| 券商已接受 | 券商接收了该操作 | 查看订单编号及真实挂单/持仓；不代表已经成交 |
| 已拒绝 | 预检、权限、时效或券商拒绝 | 查看具体说明和返回码，修正后重新分析 |
| 结果未确认 | 无最终回执或连接/超时结果不明 | 先回查 MT5，不自动重发 |

新单默认按净值 1% 分配止损预算，可设置 1%–2%，手数按步长向下取整。最小手数仍超预算时拒绝；不自动提高预算。费用、滑点和跳空可能增加实际损失。联合分析界面的合计只表示本轮新单预算，不包含账户此前全部风险。

浮动盈亏来自账户利润字段，持仓表另列库存费；历史净损益包含交易利润、库存费、佣金和手续费，不包括独立出入金等账务调整。历史表最多显示最近 1000 笔。

对冲账户可分别保留多个周期的持仓；净额账户同品种可能合并。显示“多策略合并持仓”时，整笔平仓不能当作仅关闭某个周期。交易页操作按具体编号执行，可能作用于其他来源的订单，需核对编号。

## 10. 升级与多终端

### 升级

1. 结束当前分析并退出旧客户端；已有订单仍留在 MT5/券商。
2. 更新客户端完整目录，或更新源码后重新安装依赖和打包。
3. 如通信 EA 有新版，先记录 `InpBridgeId`、`InpAllowTrading`、历史天数与 Magic，再复制新版文件。
4. 在原通信图表重新加载 EA，恢复原参数。仅复制 `.ex5` 不保证图表内存中的旧 EA 已替换。
5. 检查版本和心跳。重载导致 EA 会话改变，旧未执行指令会作废，不会自动补发。

本次仓库补齐的通信 EA 仍是 2.50；已在使用 2.50 的终端无需为说明书更新而重复安装。

### 多终端

同一 Windows 用户下的多个 MT5 通常共享公共 Files，因此每个终端使用不同通信名称，例如 `terminal_a`、`terminal_b`。客户端切换到想操作的名称，并重新核对账户和 AI 授权。不要让两个终端使用同名通信 EA。

## 11. 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 一直显示未连接 | EA 是否已成功挂载、通信名称与公共 Files 是否一致、诊断中是否有更新的心跳 |
| 提示“同名通信 EA 已运行” | 是否给每个周期都挂了通信 EA，或另一终端用了同名；同一终端保留一个，其他终端换名 |
| EA 在线但券商离线 | 检查 MT5 登录和网络连接，不用改 API Key |
| 看不到 H1 | 是否确实另开 H1 图表并挂好兼容指标、启用导出、等待历史加载 |
| 图表存在但指标不可读 | 核对指标 1.02、`InpExportAIData`、初始化、快照身份和专家日志；普通同名对象图不等于兼容数据 |
| 结构可读但本轮等待 | 查看 OB 是否失效、价格/目标证据、报价、RR、最小手数预算及具体说明；不是所有辅助条件都必须满足 |
| 提示重新开启 AI 权限 | 账户、服务器或通信目录改变；核对目标后关闭再开启开关 |
| 有计划却没有下单 | 检查 AI 开关、EA 参数、MT5/该 EA 算法交易、账户权限；人工模式还需交易页确认 |
| 一直等待 EA 或结果未确认 | 检查 EA 2.50、会话和日志；先回查真实订单，不重复提交 |
| 显示券商接受但持仓为空 | 限价挂单可能尚未成交，先查看“当前挂单”和订单编号 |
| API HTTP 400 | 看服务商返回详情；核对协议、完整地址、模型 ID、思考/输出参数，保存后重测工具调用 |
| 模型能聊天但工具测试失败 | 当前模型或路由不支持所需工具往返；更换支持工具调用的模型/协议 |
| 编译提示找不到 Json/SMCRead | 三个源文件要在同一目录；完整下载仓库，不要只下载主 `.mq5` |
| `.ex5` 下载后不能运行 | 下载二进制原文件或整个仓库 ZIP，别把 GitHub 网页另存为 `.ex5`；校验哈希，必要时用本机 MetaEditor 编译 |
| `npm ci` 后 Electron 下载失败 | 检查 npm/Electron 下载网络和本机代理，再按终端给出的 Electron 安装提示重试 |

出现问题时可提供客户端连接诊断、EA 专家日志中的相关错误行和已脱敏的回执；不要公开 API Key、账户密码、完整本机档案或交易历史。
