# 天行健交易工作台 · TianXing Client

Windows / Electron 客户端，当前版本 **2.7.0**。在独立桌面窗口中管理模型 API、本地 Skills、MT5 数据和多周期交易计划。

**本仓库开源客户端及通信 EA 2.50，并提供可安装的 EA 编译文件；不包含 MT5 指标及指标算法。** 你需要自行准备兼容的天行健 SMC 纯指标 1.02。

📖 [详细安装使用说明](docs/安装使用说明.md) · [多周期分析指南](docs/多周期分析指南.md) · [通信 EA 文件与校验](mt5/README.md)

## 功能

- 深色工作台，分析回复支持 Markdown、原文切换与复制。
- 自定义模型服务商、API 地址、密钥和模型，支持 Chat Completions、Claude Messages、Responses 等协议。
- 本地 Markdown Skills 的创建、编辑、启停、导入、导出和参考文件管理。仓库提供两份客户端技能，不包含旧项目的指标参考源码。
- 读取账户、报价、挂单、持仓、浮动盈亏和成交历史，显示连接状态与数据时效。
- 单周期策略独立保存聊天、技能和风险比例，并可按策略筛选交易记录。
- 联合分析可勾选 1–8 个图表，在一轮分析中分别评估并提交，每个周期最多一笔新限价挂单。
- AI 直接挂单开关默认关闭。开启后仍校验账户绑定、真实 OB/FVG 引用、结构外止损、RR、报价和风险预算。
- 单笔预算为账户净值的 1%–2%，联合界面显示新单预算合计；逐周期展示回执、拦截重复和结果未确认的后续提交。
- 模型接口中断后保留已发送指令记录。撤单、改单和平仓通过交易页独立确认。

## 开发运行

需要 Windows、Node.js 22 和 npm：

```powershell
npm ci
npm start
```

核心测试：

```powershell
npm test
```

隔离窗口测试，例如：

```powershell
node scripts/batch-ui-test.cjs
node scripts/ui-test.cjs
```

测试使用合成数据、本机模拟 API 和独立用户档案，不会向券商发出订单。结果写入被 Git 忽略的 `evidence/`。

打包 Windows 客户端：

```powershell
npm run package
```

输出目录为 `dist/TianXingJian-win32-x64/`。首次打包可能需要下载 Electron 运行时。

## 连接已有 MT5 环境

1. 按[安装说明](docs/安装使用说明.md)把仓库 `mt5/` 中的通信 EA 2.50 安装到 MT5，并挂载到一个图表。客户端 2.7 沿用 `json_multiline_v2` 协议。
2. 客户端填写匹配的通信名称和公共 Files 目录。文件位于公共 Files 下的 `TXJ_Client/<通信名称>/`。
3. 为需要分析的 M5、M15、H1 等周期分别打开图表，挂载你已有的兼容 SMC 指标并开启导出。同一终端只需要一个通信 EA。
4. 分析页选择单周期或多周期模式，核对目标、技能和风险预算，再发送请求。

客户端“安装通信 EA 到 MT5”按钮可复制随仓库附带的 4 个通信文件，并备份已有通信 EA 目录；也可手动安装。复制完成后需在 MT5 重新加载 EA。指标仍需自行提供。协议概要见 [docs/BRIDGE_PROTOCOL.md](docs/BRIDGE_PROTOCOL.md)。

## 一次分析多个周期

选择“多周期联合分析”，展开“选择周期与风险设置”，勾选 M5、M15、H1，核对各周期预算，然后开启“允许 AI 直接挂单”并发送：

> 分别分析勾选的 M5、M15、H1，按各周期技能和风险预算分别评估 OB 和 FVG 是否可以入场，不采用 FVG 时给出具体原因。符合条件的周期各挂一笔限价单，不满足的单独等待，最后汇总交易计划、RR 和实际执行回执。

每个周期最多一笔，按周期逐笔校验和提交。三个周期各设置 1% 时，新单预算合计约为净值的 3%，还需考虑已有订单风险。某周期等待或失败不会撤销其他已发送订单，关闭开关或停止分析也不会自动撤单。

仅分析时关闭开关或明确写“仅分析，不下单”。联合聊天按账户和周期组合分别保存，单周期聊天保留对应结果摘要。重启只恢复记录，不重发指令。

## 目录

| 路径 | 内容 |
| --- | --- |
| `src/` | Electron 主进程、模型协议、技能、策略、风险和文件通信客户端 |
| `ui/` | 桌面界面和 Markdown 显示 |
| `skills/` | 两份客户端 Markdown 技能 |
| `tests/` | Node 核心测试 |
| `scripts/` | 打包和隔离窗口测试 |
| `mt5/` | 通信 EA 2.50 的源码、读取/JSON 依赖及编译文件；无指标实现 |
| `docs/` | 安装说明、多周期指南和通信协议 |

API 密钥由 Electron safeStorage 保护并保存在本机用户档案。仓库排除用户配置、聊天、订单、日志、截图、客户端构建产物和全部指标文件（仅明确列出的通信 EA 文件例外）。技能与模型实际读取的数据会发送至你配置的服务商。

风险计算是止损金额估算，不包含全部手续费、滑点和跳空影响。测试通过不代表策略收益或券商成交保证。

## 2.7 回执与双区域评估

每轮分析自动读取 OB 与 FVG 的真实候选、状态和全局下标。模型必须分别说明是否可入场，比较后选择 OB、FVG、重叠区或等待；FVG 完全回补等不能入场的原因必须写清。有效 FVG 可以独立下单。

发送新分析或提交新交易前自动清理旧回执显示，同轮联合分析的周期回执保留。分析状态栏与交易页支持单条删除，交易页可清空全部回执。删除不会撤单，也不会移除内部去重记录。旧指令过期并收到越过有效期的有效 EA 心跳后解除全局阻塞；无法恢复历史结果时仍明确标记未知，不自动重发。
